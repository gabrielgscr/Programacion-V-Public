# Tarea: Aplicación práctica de principios SOLID

## Objetivo

Aplicar los principios SOLID mediante la programación de ejemplos funcionales que permitan comprender cómo estos principios ayudan a mejorar el diseño, mantenimiento y escalabilidad del software.

## Descripción general

En equipos de **dos estudiantes**, deberán desarrollar una pequeña solución de software que contenga **cinco ejemplos de código**, uno por cada principio SOLID.

Los ejemplos deben estar relacionados con una misma temática o contexto. Por ejemplo:

- Sistema de facturación.
- Sistema de reservas.
- Sistema de inventario.
- Sistema de biblioteca.
- Sistema de ventas.
- Sistema de gestión de usuarios.
- Sistema académico.
- Sistema de pedidos.
- Sistema de tareas.
- Otro tema propuesto por el equipo.

Cada ejemplo debe demostrar claramente la aplicación de uno de los siguientes principios:

1. **S — Single Responsibility Principle**  
   Principio de Responsabilidad Única.

2. **O — Open/Closed Principle**  
   Principio de Abierto/Cerrado.

3. **L — Liskov Substitution Principle**  
   Principio de Sustitución de Liskov.

4. **I — Interface Segregation Principle**  
   Principio de Segregación de Interfaces.

5. **D — Dependency Inversion Principle**  
   Principio de Inversión de Dependencias.

## Requerimientos del trabajo

El equipo debe programar **cinco ejemplos**, cada uno enfocado en un principio SOLID.

Todos los ejemplos deben pertenecer a una misma temática general, de manera que el trabajo tenga coherencia. Por ejemplo, si el equipo selecciona un sistema de biblioteca, los cinco ejemplos deben estar relacionados con préstamos, usuarios, libros, notificaciones, reportes u otros elementos propios de ese sistema.

Para cada ejemplo se debe incluir:

- Código funcional.
- Nombre del principio aplicado.
- Explicación breve del problema que resuelve.
- Explicación de cómo el código aplica el principio.
- Una pequeña demostración de uso del ejemplo desde el código.

Los ejemplos pueden estar integrados en una misma solución o separados por carpetas, pero debe quedar claro cuál principio SOLID se está demostrando en cada caso.

## Lenguaje de programación

El trabajo puede desarrollarse en uno de los siguientes lenguajes:

- Java
- C#
- Python

El equipo debe seleccionar un solo lenguaje para todo el trabajo.

## Exposición

Además del desarrollo del código, cada equipo deberá preparar una **exposición breve para sus compañeros**.

En la exposición, el equipo debe explicar:

- La temática seleccionada.
- Cómo está organizada la solución.
- Qué principio SOLID se aplica en cada ejemplo.
- Por qué el ejemplo representa correctamente ese principio.
- Qué problema de diseño se evita al aplicar el principio.
- Qué podría ocurrir si ese principio no se aplicara.

La exposición no debe limitarse a leer definiciones teóricas. Debe enfocarse principalmente en explicar el código desarrollado y cómo se aplican los principios SOLID en los ejemplos programados.

## Entregables

El equipo debe entregar:

1. **Repositorio en GitHub** con el código fuente.
2. **README** con:
   - Nombre de los integrantes.
   - Temática seleccionada.
   - Lenguaje utilizado.
   - Instrucciones para ejecutar los ejemplos.
   - Explicación breve de cada principio SOLID.
   - Descripción de cada ejemplo programado.
3. **Exposición para los compañeros**, donde se explique cómo se aplicaron los principios SOLID en los ejemplos desarrollados.

> **Fecha de entrega - exposición**: 18/6/2026

## Duración

La tarea tendrá una duración de **una semana**.

## Forma de trabajo

La tarea debe realizarse en equipos de **dos estudiantes**. Ambos integrantes deben participar en el análisis, diseño, programación, documentación y exposición de los ejemplos.

## Criterios de evaluación

| Criterio | Porcentaje |
|---|---:|
| Implementación correcta de los 5 principios SOLID | 40% |
| Claridad, funcionalidad y orden del código | 20% |
| Coherencia temática de los ejemplos | 15% |
| README y documentación del repositorio | 10% |
| Exposición y explicación de la aplicación de los principios | 15% |
| **Total** | **100%** |

## Consideraciones importantes

- No se aceptan ejemplos copiados directamente de Internet sin adaptación o explicación propia.
- El código debe ser claro, ordenado y funcional.
- Los ejemplos deben compartir una misma temática.
- Cada ejemplo debe demostrar de forma evidente el principio correspondiente.
- Se valorará que los ejemplos representen situaciones cercanas a problemas reales de desarrollo de software.
- No es obligatorio construir una aplicación grande; lo importante es que cada ejemplo sea comprensible y demuestre correctamente el principio SOLID correspondiente.
